# Optional A10 Implementation Plan

> Execute inline with superpowers:executing-plans and test-driven development; user authorized implementation in goal mode on main. Do not commit or push without a new request.

**Goal:** Disable A10 by default while retaining an explicit opt-in and ensuring A11, B1 and downstream classification/review remain usable in both modes.

**Architecture:** `convert_document(..., use_hierarchy=False)` bypasses the A10 builder and returns `hierarchy_json_path=None`. The completed manifest records the disabled sidecar; A5 still runs the same Docling pipeline. B1 obtains reading order, pages and container/list ancestry from canonical references when the sidecar is intentionally absent. No heading-path reconstruction occurs in the fallback.

**Tech stack:** Existing Python 3.11/uv, dataclasses, JSON and pytest; no new dependencies.

## Constraints and scope

- Preserve source corpus, historical outputs, human labels, unrelated dirty changes and stable component IDs.
- Enabled artifacts retain the historical `tmp/converted/<hash>/` location and profile; disabled artifacts use `tmp/converted/<hash>/a10-disabled/` with a distinct profile. B1/B2/B3/B4 disabled outputs similarly live under `tmp/stage_b/<hash>/a10-disabled/`.
- Required disabled outputs are Markdown, canonical JSON and manifest. Enabled mode still requires the hierarchy sidecar. Do not treat a missing enabled sidecar as a successful ablation.
- Preserve canonical JSON and original heading items unchanged. Fallback uses validated canonical body/group child order, canonical pages, and container ancestry; heading paths are empty. Lists and tables remain atomic. Do not sort text by collection index or rebuild PDF layout.
- Broken references, cycles and duplicate leaves fail; missing heading levels are irrelevant only when A10 is explicitly disabled.
- Mode plus input hashes distinguish B1 caches; downstream stages inherit separate directories and B1 fingerprints. Continue local telemetry/debug without recording absent artifacts as present.
- Pin the separate human-annotation conversion to `use_hierarchy=True` so its existing source catalogs/fingerprints do not change implicitly. Never read human labels for pipeline execution.
- This is an infrastructure ablation toggle, not a chunk-strategy redesign or an accuracy claim. B2 optionality, B3 prompts/model defaults and passage output roles stay unchanged.
